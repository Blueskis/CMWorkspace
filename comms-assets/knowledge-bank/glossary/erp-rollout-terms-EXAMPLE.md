## Terms and the plain-language gloss to pair with them on first use

**Go-live.** The date the new system or process becomes the one actually used, replacing
the old one. Pair with a plain gloss on first use in audience-facing copy: "go-live — the
date it switches over."

**Cutover.** The technical window during which data or access moves from the old system to
the new one; often a period of reduced or no access. Always state the window's start and
end, not just "there will be a cutover."

**Hypercare.** The heightened-support period immediately after go-live, usually one to
four weeks, during which support response times are faster than normal. Worth naming
explicitly in the "help" message — audiences respond well to knowing extra support exists
right when they need it most.

**UAT (user acceptance testing).** Pre-go-live testing by real users rather than the
technical team. Rarely needs to appear in audience-facing comms unless the audience itself
was part of UAT and the pack is thanking or referencing them.

out acronyms on first use per channel. This entry is where that expansion text comes from,
so five different channel drafts don't each invent a slightly different gloss for the same
term — which is exactly the kind of drift Stage 5's cross-channel consistency check is
built to catch.

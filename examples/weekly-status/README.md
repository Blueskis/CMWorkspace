# Worked Example — Meridian S/4HANA, Week 11 → Week 12 (fictional)

A complete run of the status-update pipeline over three documents, used to demonstrate and
regression-test it. **The client, the programme, the people and all the data are invented.**

The inputs are real `.docx`, `.xlsx` and `.pptx` files, generated by `make_inputs.py` so the
repo needs no Office libraries. Re-run that script only if the example data changes.

## What's here

```
inputs/week-11/, inputs/week-12/   cm-plan.docx, training-completion.xlsx, ricefwa-status.pptx
run/snapshots/                     Stage 1 — six normalised snapshots
run/changes/                       Stage 2 — one diff per document
run/change_brief.json / .md        Stage 3 — merged into one ID space, 35 changes
run/status_update.md               Stage 4 — the spoken update (written, not generated)
run/qa_report.md                   Stage 5 — PASS
```

## Reproduce it

```bash
cd examples/weekly-status
S=../../skills/status-update-agent/scripts

# Stage 1 in one command — pairs the two folders, extracts both sides, seeds the archive:
python $S/intake.py \
    --previous inputs/week-11 --previous-period "Week 11" \
    --current  inputs/week-12 --current-period  "Week 12" \
    --snapshots run/snapshots --archive /tmp/snapshot-archive

# ...or per document, which is what the committed snapshot filenames reflect:
for p in 11 12; do
  python $S/extract.py inputs/week-$p/cm-plan.docx --period "Week $p" \
      --name cm-plan -o run/snapshots/cm-plan-$p.json
  python $S/extract.py inputs/week-$p/training-completion.xlsx --period "Week $p" \
      --name training-completion -o run/snapshots/training-completion-$p.json
  python $S/extract.py inputs/week-$p/ricefwa-status.pptx --period "Week $p" \
      --name ricefwa-status -o run/snapshots/ricefwa-status-$p.json
done

for n in cm-plan training-completion ricefwa-status; do
  python $S/diff_snapshots.py run/snapshots/$n-11.json run/snapshots/$n-12.json \
      -o run/changes/$n.json
done

python $S/write_update.py run/changes/*.json -o run/change_brief.json --md run/change_brief.md
python $S/qa_update.py run/change_brief.json run/status_update.md -o run/qa_report.md
```

Expected: 35 changes across the three documents — 3 high, 26 medium, 6 low — and QA passing
with 29 changes cited and 6 explicitly waived.

## What it demonstrates

**One shape, three formats.** A Word plan (headings plus an activity table), an Excel
training tracker and a PowerPoint status deck all normalise into the same snapshot, and the
diff never branches on document type.

**Object-level tracking through a re-titled deck.** The RICEFWA bullets carry object IDs, so
`FI-R-014` is tracked across weeks as its own item — `In Build → In Test`, `amber → green` —
even though slide 1's title changed from "Week 11" to "Week 12". The title change itself is
caught by the second-pass similarity matcher and reported as a rename at 0.96 similarity,
not as a slide deleted and a slide added.

**Materiality separates the news from the movement.** 35 changes, 3 of them high: two
warehouse leads whose training due date slipped a fortnight, and a comms deliverable that
slipped a week. Those three are what the meeting is actually about.

**The same news isn't told twice.** Five completion percentages jumping alongside their
status changes are downgraded and marked `subsumed_by` the status change they follow.
Meanwhile "14 named champions" → "16 named champions" is a 96%-similar sentence that stays
material, because the numbers in it moved.

**Connections across documents are the value, and are marked as judgement.** The update ties
the training slip, the risk that opened in the plan and the steering escalation into one ask
about Logistics super-user backfill. No single document contains that; every part of it is
cited, and the connection itself is marked `[JUDGEMENT]`.

**Intake survives client file naming.** The example's filenames are tidy, but the pairing
strips version noise, so these all pair correctly:

```
Meridian CM Plan v4 (for review).docx   ↔  Meridian CM Plan v5 FINAL.docx
Training Completion Tracker WK11 2026-08-14.xlsx  ↔  ...WK12 2026-08-21.xlsx
RICEFWA Status Wk11 DRAFT.pptx          ↔  RICEFWA Status Wk12.pptx
```

while a `Steering Pack.pdf` is reported as skipped, a document only present this week is
reported as new and undiffable, and one present only last week is reported as missing.
Run `intake.py --dry-run` to see the pairing before anything is written.

**Provenance is enforceable.** Every claim in `status_update.md` carries a `[C#]` or a
`[JUDGEMENT]`. Adding an uncited sentence, or citing a `[C99]` that doesn't exist, fails QA
— try it.
